# MohaMind v0.3.0 — WhatsApp self-chat and easier onboarding

Connect your existing agent to WhatsApp's Message Yourself chat, configure a new
installation with four prompts, and keep model-driven tool execution within
configurable limits.

## WhatsApp through QR linking

- Link an existing account with `uv run mohamind whatsapp setup`, then run
  `uv run mohamind whatsapp` to chat using your current MohaMind memory.
- Text self-chat only: other contacts, groups, history imports, media, and the
  bridge's own replies are ignored.
- Session credentials and hashed message receipts live separately from memory.
  Requests are recorded before execution to prevent automatic replay after a restart.
- Use `uv run mohamind whatsapp --schedule` for scheduled notifications. Run only
  one scheduler against a memory directory.
- Requires Node.js 20+ and npm. Dependencies are optional and installed during linking.

The Baileys bridge is an unofficial WhatsApp Web integration and uses a pinned
release candidate. Account restrictions and protocol compatibility changes are
possible. Offline checks cover filtering and message handling; live pairing with
a real account has not yet been verified.

## Easier setup

- `setup --quick` asks for the provider, key, timezone, and language.
- First-run setup preserves existing `.env` configuration and refreshes settings
  before starting the agent.
- Hidden key entry, placeholder-key rejection, and timezone validation catch common
  setup mistakes. Shell variables override `.env` consistently.
- Noninteractive runs explain how to configure a missing key instead of waiting for input.
- Doctor returns a failing exit status for missing keys or invalid timezones and
  distinguishes local checks from provider connectivity.
- Includes a first-session walkthrough and a prepared five-person usability study.
  The human study has not yet been conducted.

## Predictable tool execution

- Malformed JSON and non-object arguments are rejected before tool execution.
- Chat, daily briefings, and weekly reviews enforce tool-call limits.
- Cooperative async timeouts and marked result truncation bound individual tool use.
- Chat requests a final summary when its tool budget is exhausted.
- External MCP sessions keep startup and cleanup in the same owning task, with
  regression coverage for startup timeouts and shutdown from another task.

Timeouts cannot interrupt blocking synchronous code or undo actions already accepted
by external services. These settings do not impose whole-turn token or spending limits.

## Upgrade

Update your checkout after merging the PR, then run `uv sync`. Keep any optional
extras you already use, such as `uv sync --extra voice`. Existing installations
do not need to rerun quick setup. Restart the agent to load the new code.

No personal-memory migration or reset is required. Keep your existing working
directory, `.env`, `MEMORY_DIR`, and credentials. WhatsApp pairing uses its own
directory under `credentials/whatsapp` by default.

Reminder dates still use Asia/Riyadh in the existing reminder flows; changing the
schedule timezone does not yet convert all reminder parsing and storage.

## Validation

Python regression tests, Ruff, Node message-filtering tests, bridge syntax checks,
the staged public-file check, and wheel packaging are checked for the PR. GitHub CI
covers Python 3.12 and 3.14. API calls and WhatsApp message delivery are mocked in tests.
